## menuBuilder.js

**Purpose:** Builds the one menu panel injected into Creatio pages: the Settings (gear) and developer news (open book) icons in its bottom-right corner (top-right with the Options switch), and columns that always open together — the developer news (only while there are unread news, added by `shellIndicator`), the navigation items, and the actions that change the site (RestartApp, FlushRedis, autologin toggle) on the right.

**Public API:**
- `buildMenuContent(buttonWrapper, pageType): void` — entry point; builds both menus and attaches them to `buttonWrapper`

**Key decisions:**
- The columns are `.csl-nav-column` and `.csl-actions-section` (both `role="group"`) inside `.csl-menu-columns`, which sits in `.csl-menu-body` (a flex row) after the news column `.csl-news-column` when it is shown. `.csl-menu-header` holds the icon buttons `.csl-menu-icon-btn`: Settings (`<button>`, `title`/`aria-label` "Settings", opens the options page) and the news page (`<a target="_blank">` to `ARCHIVE_URL`, title "Developer news"), the book rightmost. Settings used to be the last row of the navigation column under a divider; as an icon it no longer competes with the navigation items. By default the header is absolutely positioned in the bottom-right corner of the panel, over the empty end of the actions column (2–3 items against 8 navigation items), so it adds no height; a header row at the top added a 32 px strip above the items. `menuIconsAtTop` in `chrome.storage.sync` (Options → Menu → "Show the Settings and news icons at the top of the menu") puts `ICONS_TOP_CLASS` (`csl-menu--icons-top`) on the panel, which makes the header a static row in the top-right corner. `applyIconsPosition` reads the switch on every open, so a change applies without a reload, and places the menu again only when the class changed. `attachShellNews` gets `menuBody` (where the column goes) and `onLayoutChange`, which places the open menu again when the column appears or disappears. The actions used to be a second menu beside the first; the pair was placed as two boxes and drifted apart near the screen edges (one under the other, off the screen, over the news flyout). A single list with the actions in the middle was tried and rejected: it mixed safe and unsafe items and made the list twice as long to scan. One panel with two columns keeps them apart and moves them as one box. Both halves of the panel have the same width (a `1fr 1fr` grid in `menu-item.css` without a gap, 6 px of padding on each side of the divider, and the divider drawn with an inset shadow so it takes no width): the wider of their longest captions plus 20 px, not a fixed minimum — with fixed minimums the navigation column carried an empty strip on the right. Items come from `ACTION_DETAILS`; RestartApp and FlushRedisDB are added synchronously on every open so the menu has its full height when it is placed; the autologin item needs `chrome.storage.sync`, is added when a last-login profile exists for the current origin, and the menu is placed again once it is there.
- Autologin enable/disable reads and writes `chrome.storage.sync` directly (not via background) because it modifies only the profile array, not runtime state.
- `safeSendMessage` is used for script execution and disable-autologin to route through the background worker.
- Menu captions come from `SCRIPT_LABELS` when present, otherwise from the script name with underscores replaced. This lets a caption be corrected without renaming the script file that `executeScript` loads (`Application_Managment` is shown as "App Hub").
- There is one button ("Clio satellite"); the separate actions button is gone. Its click opens the menu (`openMenu`) and a second click, a click on the page or picking an item closes it (`hideMenu`). A click inside the menu that is not on an item keeps it open. `monitorButtons` only checks for this button.
- Visual styling of the buttons and menus lives in `menu-item.css` (the "Visual refresh" block at the end overrides earlier rules); the divider color is set inline because Creatio styles override `mat-divider`.

- The extension container is appended to `<html>`, not `<body>`: Creatio marks `<body>` as `inert` while Shell loads, which would block clicks and focus on the visible buttons.
- Icons are inline duotone SVGs (`MENU_ICONS.svg`, `ACTION_DETAILS.icon`, and the button icon here): outline `currentColor`, accent `var(--csl-icon-accent)`, no ids/masks so they can be inlined many times. Colours are set in `menu-item.css`.

- A click on the docked edge blob opens the same menu at once (`onBlobClick`), next to the blob (`adjustMenuPositionAtEdge`), and the buttons stay in the blob: one click shows the menu, every action is two clicks away. A second click on the blob closes it. `blobAnchor` remembers the edge and box of the blob, so a menu that is placed again (the actions or the news column arrive) stays next to the blob; opening from the button clears it. The buttons that come out of the blob after a 2 s hover still run `openMenu` (`onPeekShown`) and the menu is placed by `adjustMenuPosition`; the outside-click handler ignores clicks on the blob, since that click is what opened the menu.
- The orange dot of the "Clio satellite" icon carries the class `csl-icon-dot`: `edgeBlob.js` flies the dot of the blob into it and back.
- `createScriptsMenu()` attaches the developer news indicator (`attachShellNews`) last and isolates it: a sync throw or async rejection is logged and never marks the menu as failed, so news can not trigger the menu re-creation loop.

**Dependencies:** `debug.js`, `state.js`, `pageDetection.js`, `menuConfig.js`, `menuVisibility.js`, `analytics.js` (usage events), `news/shellIndicator.js` (news column), `news/newsCards.js` (`ARCHIVE_URL` for the book icon)
- Usage statistics: opening the menu sends `menu_open {menu: 'navigation'}`; a click sends `menu_click {menu, item}` with `menu: 'navigation'` for navigation items and the Settings icon and `menu: 'actions'` for the actions; the book icon sends `news_archive_open {surface: 'shell'}`, as before the merge, so the reports stay comparable (see `analytics.md`).
