## 2026-10-07 — Developer news: implementation (branch feature/developer-news-strip)

**What changed:** New modules in `src/news/` (core rules, storage, model, cards, video dialog, login strip, Shell indicator) bundled into `content.js`; `news/newsFetcher.js` loaded by `background.js` with `importScripts` (feed + media fetching, `getNews`, `getNewsMedia`, `openNewsArchive` messages); `styles/news.css` added to both content-script CSS lists in `manifest.json`; `src/index.js` mounts the login strip on login pages; `menuBuilder.createScriptsMenu()` attaches the Shell indicator; Options got a "Developer news" card (on/off, roles, open all news); the login dropdown got "All developer news…". Privacy policy and the permission notes in all agent instruction files mention the feed download.

**Why:** Show clio-news to extension users without extension releases, per `docs/features/developer-news.md`. Late requirement: a new user sees only the 3 newest items of the last month (`onboardingSkip`, `newsSkipped`), and the full feed is always reachable in a new tab from login, Shell and Options.

**Decision:** The worker fetches and caches the raw feed (Creatio CSP/CORS never apply, the page never sees the URL); content scripts validate it, so validation lives in one unit-tested module. Images go through the worker as data URLs because self-hosted instances may block external `img-src`. The Shell flyout sits inside the menu container so existing outside-click handling keeps working. E2E caught a CSS bug: `display: flex !important` on the menu row beat the `hidden` attribute, so `[hidden]` rules now come last with the same specificity. Not done yet: the extension-page player fallback (needs a spike against YouTube's referrer check) and reactions (needs the API).
